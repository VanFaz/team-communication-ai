# ИИ-анализ командной коммуникации — современная версия курсового проекта

Тема курсового проекта:

> **Программная реализация прототипа ИИ-системы анализа командной коммуникации**

Проект переработан из базового MVP в более современный прототип. Теперь система ориентирована не только на расшифровку речи, но и на анализ структуры командного взаимодействия: кто говорил, когда говорил, были ли перебивания, как распределялось участие, какие реплики выглядели конфликтными или поддерживающими.

## 1. Что делает система

Пайплайн обработки:

```text
аудио/видео
→ FFmpeg: WAV 16 kHz mono
→ ASR backend
   → WhisperX: расшифровка + word-level timestamps
   → pyannote community-1: современный локальный speaker diarization
   → faster-whisper: локальный fallback без diarization
   → OpenAI gpt-4o-transcribe-diarize: optional API backend
→ NLP-анализ реплик
   → токсичность
   → эмоция по тексту
   → коммуникативная функция реплики
→ метрики командной коммуникации
→ отчёты HTML / CSV / JSON / Markdown
```

## 2. Главное отличие от первой версии

| Было | Стало |
|---|---|
| faster-whisper как единственный ASR | pluggable ASR backend: `auto`, `whisperx`, `faster-whisper`, `openai-diarize` |
| все реплики `SPEAKER_00` | поддержка diarization по говорящим через WhisperX/pyannote |
| только сегментные таймкоды | word-level timestamps при WhisperX/faster-whisper |
| простые метрики | метрики по говорящим, балансу участия, перебиваниям, конфликтности, поддержке |
| модели загружались при каждом запуске | кэширование ASR/NLP-моделей в рамках процесса |
| токсичность считалась грубо по максимуму любого label | гибридная оценка: ML-модель + словарная калибровка для мата, оскорблений и ASR-искажений |
| только HTML/CSV/JSON | добавлен Markdown summary для вставки в пояснительную записку |

## 3. Рекомендуемый режим для курсового

Лучший локальный вариант для демонстрации:

```text
backend = auto или whisperx
model = small или medium
language = ru
enable_diarization = True
```

Если установлен WhisperX, pyannote и задан `HF_TOKEN`, система выполнит разделение говорящих. По умолчанию для локального diarization выбран `pyannote/speaker-diarization-community-1`; при проблемах совместимости можно указать `pyannote/speaker-diarization-3.1`. Если WhisperX не установлен, режим `auto` переключится на `faster-whisper`, чтобы проект всё равно запускался.

## 4. Установка

### 4.1. Требования

- Python 3.11 рекомендуется.
- FFmpeg должен быть установлен и доступен из командной строки.
- Для быстрой работы желательно GPU, но базовый режим работает на CPU.

### 4.2. Создание окружения

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Для современной локальной версии с WhisperX и diarization:

```powershell
pip install -r requirements_modern_asr.txt
```

### 4.3. Настройка токенов

Скопируйте `.env.example` в `.env`:

```powershell
copy .env.example .env
```

Для локального разделения говорящих через pyannote заполните:

```text
HF_TOKEN=...
DIARIZATION_MODEL=pyannote/speaker-diarization-community-1
```

Для API-backend заполните только при необходимости:

```text
OPENAI_API_KEY=...
```

По умолчанию проект не отправляет аудио во внешний API. OpenAI backend используется только при выборе `openai-diarize`.

### 4.4. Проверка настройки

После заполнения `.env` можно проверить окружение:

```powershell
python check_setup.py
```

Если для pyannote появляется `403` или `Cannot access gated repo`, нужно открыть страницу модели `pyannote/speaker-diarization-community-1` на Hugging Face, нажать принятие условий доступа и убедиться, что `HF_TOKEN` создан в том же аккаунте с правом `Read`. После этого перезапустите PowerShell и приложение.

## 5. Запуск через веб-интерфейс

```powershell
python app.py
```

В интерфейсе:

1. загрузите аудио или видео;
2. выберите `backend = auto`;
3. выберите модель `small`;
4. оставьте язык `ru`;
5. включите разделение говорящих;
6. нажмите **Запустить анализ**.

На выходе будут:

- краткий JSON-результат;
- таблица реплик;
- `report.html`;
- `utterances.csv`;
- `analysis.json`;
- `summary.md`.

## 6. Запуск через консоль

Базовый запуск:

```powershell
python analyze_file.py samples\your_audio.mp3 --out output --backend auto --model small --lang ru
```

Принудительно WhisperX:

```powershell
python analyze_file.py samples\your_audio.mp3 --backend whisperx --model small --lang ru --min-speakers 2 --max-speakers 5 --diarization-model pyannote/speaker-diarization-community-1
```

Fallback без разделения говорящих:

```powershell
python analyze_file.py samples\your_audio.mp3 --backend faster-whisper --model small --lang ru --no-diarization
```

API-вариант с diarization:

```powershell
python analyze_file.py samples\your_audio.mp3 --backend openai-diarize --lang ru
```

## 7. Что означают результаты

### Индекс качества коммуникации

`communication_quality_score` — учебный интерпретируемый индекс от 0 до 100. Он не является психологическим диагнозом. Он агрегирует формальные признаки:

- среднюю токсичность;
- долю конфликтных реплик;
- наличие поддерживающих реплик;
- долю вопросов;
- баланс участия говорящих;
- возможные перебивания/пересечения речи.

### Метрики по говорящим

В отчёте есть блок `speaker_metrics`:

- `num_speakers` — число обнаруженных говорящих;
- `speakers` — число реплик и время речи по каждому говорящему;
- `speaker_balance_turns` — баланс числа реплик;
- `speaker_balance_time` — баланс времени речи;
- `interruptions_count` — возможные перебивания или пересечения речи.


### Гибридная калибровка токсичности и эмоций

Для коротких игровых или командных реплик чистая текстовая модель эмоций может ошибаться: например, фраза с матом и прямым оскорблением иногда получает `neutral`, потому что модель обучалась на более общем корпусе и плохо учитывает ASR-искажения, сленг и неполные фразы. Поэтому в прототип добавлен слой доменной калибровки:

- ML-модель по-прежнему остаётся основным источником оценки;
- словарь агрессивных и ненормативных маркеров только повышает риск, если в тексте есть очевидная брань/оскорбление;
- если токсичность высокая и есть маркеры агрессии, эмоция корректируется в `anger`;
- в отчёте сохраняются поля `toxicity_source` и `emotion_source`, чтобы было видно, где сработала модель, а где правило.

Это не является полноценным дообучением модели. Для курсового проекта корректнее описывать это как гибридный ML + rule-based подход и доменную постобработку результатов.

### Функции реплик

Каждая реплика получает признаки:

- `toxicity_score`;
- `emotion_label`;
- `emotion_source` — источник эмоции: модель, правила или словарная корректировка;
- `utterance_type`;
- `communication_function`.

Примеры функций:

- координация действий;
- поддержка команды;
- уточнение информации;
- критика/обсуждение ошибки;
- деструктивное взаимодействие;
- информационная реплика.

## 8. Что писать в курсовой

Корректная формулировка:

> Разработан программный прототип ИИ-системы анализа командной коммуникации, реализующий обработку аудио- и видеозаписей, автоматическое распознавание речи, выделение временных границ реплик, опциональное разделение говорящих, классификацию реплик по эмоциональным и коммуникативным признакам, расчёт агрегированных метрик и генерацию аналитического отчёта.

Важно: система не ставит психологические диагнозы и не заменяет эксперта. Она автоматически извлекает формальные маркеры коммуникации и помогает быстрее найти фрагменты, требующие ручного анализа.

## 9. Ограничения

- Качество diarization зависит от шума, количества говорящих, микрофонов и перекрытия речи.
- В локальном режиме pyannote требует Hugging Face token и принятие условий модели.
- Эмоция определяется по тексту, а не по акустике голоса; для явной брани используется дополнительная словарная калибровка.
- Индекс качества коммуникации является учебной эвристикой, а не валидированной психологической шкалой.
- Для русского игрового/спортивного сленга может потребоваться дообучение классификатора реплик.
