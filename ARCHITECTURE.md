# Архитектура современного прототипа

## Цель

Система предназначена для автоматизированного анализа командной коммуникации по аудио- или видеозаписи. В отличие от обычной расшифровки, прототип извлекает признаки взаимодействия участников: распределение речи, возможные перебивания, поддерживающие и конфликтные реплики, эмоциональный фон и флаги риска.

## Основные модули

```text
app.py                 — Gradio UI
analyze_file.py        — CLI-интерфейс
src/audio_utils.py     — FFmpeg-конвертация и утилиты времени
src/asr.py             — ASR backends: WhisperX, faster-whisper, OpenAI diarize
src/text_models.py     — токсичность, эмоции, функция реплики
src/metrics.py         — метрики командной коммуникации
src/reporting.py       — HTML/CSV/JSON/Markdown отчёты
src/pipeline.py        — объединение всех этапов
```

## ASR backend design

### `auto`

Режим по умолчанию. Сначала пытается использовать WhisperX, потому что он лучше подходит для анализа коммуникации: поддерживает word-level timestamps и speaker diarization. Если WhisperX не установлен, переключается на faster-whisper.

### `whisperx`

Локальный современный pipeline:

1. ASR-модель Whisper/faster-whisper внутри WhisperX.
2. Выравнивание слов для более точных таймкодов.
3. Diarization через pyannote community-1 при наличии `HF_TOKEN`.
4. Назначение speaker labels словам и сегментам по максимальному пересечению временных интервалов.

### `faster-whisper`

Локальный fallback. Используется, когда diarization не нужна или когда WhisperX трудно установить на целевом ПК. Даёт расшифровку и word timestamps, но не определяет говорящих.

### `openai-diarize`

Опциональный API-backend с built-in diarization. Не используется автоматически, чтобы аудио не отправлялось во внешние сервисы без явного выбора.

## NLP-анализ

Каждая реплика проходит несколько уровней анализа:

1. токсичность;
2. эмоция;
3. тип реплики;
4. коммуникативная функция.

В случае недоступности моделей система использует rule-based fallback, чтобы демонстрация не срывалась из-за отсутствия интернета или проблем с загрузкой моделей.

## Метрики

Система рассчитывает:

- количество реплик;
- среднюю токсичность;
- доминирующую эмоцию;
- доминирующий тип реплик;
- долю поддержки;
- долю вопросов;
- долю конфликтных реплик;
- число говорящих;
- баланс участия по репликам и времени речи;
- возможные перебивания/пересечения речи;
- учебный индекс качества коммуникации.

## Почему это соответствует теме курсового

Тема проекта — не просто распознавание речи, а программная реализация прототипа ИИ-системы анализа командной коммуникации. Поэтому архитектура строится вокруг полного цикла:

```text
получение речи → структурирование по времени и говорящим → анализ содержания → агрегированные метрики → интерпретируемый отчёт
```

Такой подход показывает не только использование готовой ASR-модели, но и разработку прикладной аналитической системы поверх результатов распознавания.
